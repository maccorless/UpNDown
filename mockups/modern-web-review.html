1. Native dialog replaces 9 custom overlays

The settings panel rebuilt with <dialog>. Open it, press Esc, click outside, or Tab around: focus stays inside and returns to the button.

Now

<div className="modal-backdrop" role="presentation"
     onClick={onClose}>
  <div className="panel settings-modal"
       role="dialog" aria-modal="true"
       aria-label="game settings"
       onClick={e => e.stopPropagation()}>

Suggested

<button command="show-modal"
        commandfor="settings">Settings</button>
<dialog id="settings" closedby="any"
        aria-labelledby="settings-title">
  <form method="dialog"> ... </form>
</dialog>

Game Settings

Removed from React: role="dialog", aria-modal, the backdrop click handler, stopPropagation and the manual Esc handlers. closedby is not in Safari yet, so click-outside there uses the small fallback at the bottom of this page; Esc and the back gesture work everywhere.

3. Focus, press and reduced motion a11y

Tab through these. The ring is a single rule. The pulsing pile is the existing "backward ten" effect, now opt-in: with reduced motion on, it simply does not animate.

:focus-visible { outline: 3px solid var(--focus); outline-offset: 2px; }
button:active  { transform: translateY(1px) scale(.98); }
.pile { @media (prefers-reduced-motion: no-preference) { animation: ... } }

Do not use a global animation-duration: 0.01ms reset; the guide warns it can make animations more jarring. Handle each animation on its own. Any JS that waits for animationend must continue if no animation ran.

Suggested order of work

1) Focus ring, reduced motion and dvh (one hour, no behaviour change). 2) Extract one Modal component backed by <dialog> and move the 9 overlays onto it. That fits the rule in CLAUDE.md to extract components rather than grow App.tsx. 3) Dark tokens. 4) Settings sliders, if you agree.

Not recommended now: view transitions for card plays. The guide covers them, but I did not review how the board updates on server pushes, so I would not add them without that check.
